# Dashboard Redesign Example

## Request

```text
Use DesignForge to redesign this operations dashboard. Preserve the existing data model and routes. Improve scanning, responsive behavior, keyboard focus, empty states, and chart accessibility.
```

## Discovery Summary

- Page goal: help operators identify what needs attention.
- Audience: repeat users working quickly.
- Visual direction: dense, quiet, utilitarian, and precise.
- Primary risk: making a dashboard look like a marketing page.

## Expected DesignForge Behavior

1. Audit current layout, components, and available scripts.
2. Prioritize information density and clear status hierarchy.
3. Avoid oversized hero sections or decorative card-heavy layouts.
4. Add visible focus states and keyboard-safe controls.
5. Provide empty, loading, and error states.
6. Run lint, tests, type checks, and build only when those scripts exist.

## Representative Output Structure

- Persistent navigation
- Compact page header with primary actions
- KPI summary with accessible labels
- Filters and saved views
- Data table with clear states
- Chart alternatives or summaries
- Final PASS/WARNINGS/FIXES/BLOCKED classification
